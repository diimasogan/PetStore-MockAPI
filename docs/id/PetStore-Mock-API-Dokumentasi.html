Ringkasan eksekutif

PetStore Mock API adalah project Boomi Web Services kecil yang meniru dua operasi Swagger Petstore publik: ambil pet berdasarkan ID dan buat pet. Project ini memberi tim front-end dan integrasi endpoint yang stabil untuk dikembangkan sebelum back end sebenarnya tersedia.

Project ini juga menjadi referensi rapi untuk pola berlapis yang dipakai di project yang lebih besar: proses listener yang tipis, sub-proses berisi logika bisnis, profil JSON sebagai kontrak, dan respons error bergaya Petstore.

Tujuan

Membuka jalan tim klien

Developer front-end dan mobile langsung mendapat API yang kompatibel dengan Petstore sejak hari pertama.

Uji kontrak

Respons yang dapat diprediksi — termasuk error — memudahkan pengujian penanganan error di klien.

Pola referensi

Menunjukkan pola API → [SUB], decision regex, dan respons Message-shape dalam bentuk paling sederhana.

Yang didemonstrasikan

Web Services Server

Mengekspos proses Boomi sebagai endpoint REST di shared web server Atom Cloud.

Parameter query sebagai DPP

petId diterima sebagai dynamic process property query_petId.

Profil JSON

j.PetStore.Pet mengikuti skema Pet Swagger Petstore dan dipakai untuk akses field di decision.

Validasi input

Decision regex menolak ID yang salah dan nama kosong sebelum langkah lain berjalan.

Error yang konsisten

Error memakai bentuk ApiResponse Petstore: code, type, message.

Observabilitas

Shape Notify mencatat setiap pet yang diterima di process log.

GET dengan petId kosong atau bukan angka200{"code": 400, "type": "error", "message": "Invalid ID supplied"}

Catatan: proses tidak mengatur status HTTP, sehingga listener menjawab 200 bahkan untuk error. Klien perlu mengecek type == "error" di body.

Desain proses

ProsesShapeLogika
PetStore API - Get PetStart (WSS Listen: PetStore WSS Get Pet) → Process Call → Return DocumentsMenerima GET, meneruskan request ke sub-proses.
[SUB] PetStore Get PetStart (passthrough) → Decision “Valid Pet ID?” → Message → Return Documentsquery_petId cocok dengan ^[0-9]+$ → Pet mock dengan id tersebut; selain itu ApiResponse 400.
PetStore API - Create PetStart (WSS Listen: PetStore WSS Create Pet) → Process Call → Return DocumentsMenerima body JSON, meneruskannya ke sub-proses.
[SUB] PetStore Create PetStart (passthrough) → Decision “Pet Name Provided?” → Notify / Message → Return Documentsname cocok dengan .*\S.* → Notify “Pet accepted: {1}” dan body dikembalikan; selain itu ApiResponse 405.

Keputusan desain

  • Listener tipis, logika mudah diuji. Proses [SUB] memakai start passthrough, sehingga bisa dijalankan di Test Mode dengan dokumen contoh — tanpa perlu panggilan HTTP.
  • Decision regex membuat validasi eksplisit dan terlihat di canvas.
  • Message shape menghasilkan JSON Petstore yang persis sama, sehingga klien yang dibuat untuk Swagger Petstore bisa langsung dipakai.
  • Tanpa penyimpanan secara sengaja: mock bersifat stateless dan aman dipanggil berulang kali.

Struktur repositori

  • active-development/ — XML komponen Boomi (proses, operasi, profil).
  • portal/ — mockup konsol web statis.
  • docs/ — dokumentasi ini (sumber di docs/_source/).
  • .env.example — pengaturan yang diperlukan untuk push dan deploy; salin ke .env (tidak pernah di-commit).

Penyiapan & deployment

  1. Salin .env.example ke .env lalu isi akun Boomi, API token, folder tujuan, environment, dan test atom.
  2. Push komponen di active-development/ ke folder platform.
  3. Deploy PetStore API - Get Pet dan PetStore API - Create Pet ke environment Atom Cloud dengan shared web server aktif.
  4. Panggil endpoint dengan user shared web server (Basic auth) dan jalankan kasus uji di atas.

Keterbatasan & langkah berikutnya

Data GET statis

GET selalu mengembalikan “doggie”; pet yang dibuat tidak disimpan.

Kode status HTTP

Atur status HTTP (400/405) lewat header respons agar klien tidak perlu memeriksa body.

Penyimpanan

Simpan pet di database atau Disk V2 dan cari berdasarkan id.

Operasi tambahan

Tambahkan PUT /pet, DELETE /pet/{petId}, dan findByStatus.

API Management

Publikasikan lewat komponen Boomi API Service dengan spesifikasi OpenAPI.

Validasi skema

Validasi status terhadap available | pending | sold serta tipe setiap field.
